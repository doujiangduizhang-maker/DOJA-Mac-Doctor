# DOJA Mac Doctor

面向 Apple Silicon / macOS 14+ 的 Swift + SwiftUI 原生磁盘诊断应用。简体中文、深色界面，无第三方依赖、Electron 或云端服务。

当前版本 **0.3：自动扫描、本机空间历史与勾选后安全处理**。源码独立于同目录的其他项目。扫描不会处理文件；只有勾选通过安全核实的缓存并点击“一键移至废纸篓”后才执行。重要或用途未确认的文件不能勾选。

## 打开与使用

构建后双击 `dist/DOJA Mac Doctor.app`。可以留在外置盘运行；关闭主窗口后继续驻留菜单栏，显示内部盘当前可用空间。菜单栏提供打开窗口与退出。

1. **打开软件就开始只读扫描**：当前用户目录、`/Applications`、`/Library`，以及之前添加的外置盘或开发项目目录。每次启动只自动检查一次，不持续进行全盘扫描；支持暂停与取消。
2. 首页直接显示“可放心处理”和“需要确认 · 暂不处理”，同时展示完整路径、用途、大小和风险。没有权限、扫描未完成或有未知条目的项目不会进入处理列表。
3. **勾选 → 一键移至废纸篓**。默认不勾选，不自动移动文件；点击按钮就是对当前已勾选项目的确认，不再弹出重复的确认窗口。处理前再次核对身份、完整文件清单、目录范围和应用运行状态。
4. 移动完成后保留逐项处理记录，自动重新扫描，更新真实容量。不会清空废纸篓，也不会将“已移动的文件大小”冒充“已释放空间”。
5. 正在运行的 Codex 缓存会保留，退出 Codex 后重新检查才可勾选；本应用不会结束其他应用的进程。影视缓存、工程、素材、会话、日志和未知副本继续标出风险，不直接处理。
6. “详细扫描”保留最大 20 个目录、最大 50 个文件、最近七天 ≥100 MiB 文件、类型统计和未扫描项。需要检查外置素材盘或其他目录时才添加范围，添加完成立即开始扫描。
7. 可导出真实 JSON 报告。报告包含私有路径，保存与分享由你决定。保留最多 2000 个最大目录及根目录、1000 条覆盖问题和 500 条建议，并明确记录数量；超过 8 MB 不写入。总量与完整性仍来自全部扫描数据，未导出的条目不视为不存在。
8. **每分钟记录空间变化**，关闭主窗口后仍通过菜单栏运行。重启应用会加载已有本机历史；睡眠、退出或缺失读数之间不补造数据。10 分钟内内部盘可用空间减少超过 3 GB 时记录异常，保留内存、Swap 与可核实的同卷目录线索，原因始终待确认。
9. 已添加的目录优先成为重点检查位置，随后选择实际存在的 Codex 日志、会话、崩溃报告和影视缓存等，最多 8 个。系统事件只标记变动；每轮共享约 5 秒检查预算、每目录最多 20,000 个文件，至少隔 5 分钟核对。大目录或权限受限会明确显示未完整，不能当作空目录。

常见目录使用本机应用已有的普通文件访问权限，macOS 隐私限制仍然有效；遇到系统授权提示时由用户决定。应用不会默认请求管理员权限，也不会更改系统保护。拒绝访问的位置保留为覆盖问题，不当作空目录。云端占位文件不触发下载。

## 数字含义

**文件大小**是内容长度；目录文件大小汇总包括其子目录，目录榜单不能相加。硬链接各路径分别贡献文件大小和文件数量。

**分配空间**读取 `st_blocks × 512`，包含目录自身的分配块。扫描汇总按磁盘卷与 inode 对硬链接去重，将其块归属到首次遇到的路径；文件详情显示每个路径自己的原始分配值。不同遍历顺序可能改变硬链接的目录归属。

**实际可回收空间**无法通过元数据扫描精确确定。APFS 克隆共享块、快照、其他硬链接、打开但已删除的文件及系统数据均可能影响释放量。建议只提供 0 到分配空间的估算上限，且保护文件、多个硬链接的文件或不完整目录不估算。不能累计父子目录，也不能把估算上限当成承诺。

磁盘顶部容量使用内部 APFS 数据卷 `/System/Volumes/Data` 的 `statfs` 可用容量，包含 APFS 共享容器的实际空间约束，不能用授权目录汇总反推整个硬盘的占用。系统“可清除空间”的乐观估计不计入当前可用数字。[Apple APFS 文档](https://developer.apple.com/documentation/foundation/about-apple-file-system)解释克隆、快照与共享容器的关系。

移至废纸篓通常不立即释放空间；清空后，共享块与快照也可能继续保留数据。应用只提供确认后的移动，不提供清空废纸篓或永久删除。

## 处理安全与恢复

当前可执行范围非常明确：用户目录内固定应用路径的 Codex GPU / Code / Shader 等缓存叶目录。仅有绿色标签还不够；逐项核实全部文件都是已知缓存名称格式、未混入工作文件、没有链接或云端占位项、已完整扫描、权限足够且 Codex 已退出，才显示勾选框。整个 Application Support、整个 Codex 数据目录、未知临时目录和黄色/红色项均不能处理。

勾选保留最初核实的文件身份清单，执行前重新比较；文件新增、替换、时间或大小变化、应用重新运行、范围失效时跳过并解释原因。计划超过十五分钟后拒绝处理，需重新检查。

为避免错误覆盖，缓存先经同卷排他移动进入可见的 `DOJA Mac Doctor Recovery 原名称 UUID` 待处理位置，再调用系统废纸篓。失败尝试排他恢复，不覆盖新建文件；不能恢复时保留实际核对的恢复路径。处理记录和扫描发现的待恢复目录可复制路径或在 Finder 查看。普通退出会等待正在执行的移动完成；强制结束仍可能留下可见恢复目录，应用会提示核对，绝不会自动删除它。

进入废纸篓的目录可能使用待处理名称。Finder 恢复后需核对原完整路径并改回原缓存名称；不能承诺“放回原处”会自动恢复为 GPUCache 等名称。缓存也可由 Codex 重建。完整限制与系统路径接口的并发边界见 [清理安全说明](docs/CLEANUP-SAFETY.md)。

## 专项诊断

Codex 会分别识别实际存在的 Crashpad/pending、应用缓存与日志、本地会话和工作目录、开发项目依赖/缓存，以及用途尚待确认的临时构建或签名副本。`.codex` 的会话、配置、工作树、备份、技能与其他不明工作数据默认保留。崩溃报告与日志保留故障排查风险说明；大或近期修改不等于异常。

影视诊断通过实际目录名称与已授权根目录的有限浅层发现识别 Resolve / 剪映 / CapCut 线索。缓存和代理盘可由项目或版本自定义；此版本不解析软件配置内容，名称匹配不能证明用途，用户必须在原应用内核对目录。原始素材、未知媒体、工程、项目数据库、草稿、画廊与作品输出受到保护。

完整扫描的每个文件都参与保护证据判断，即使该文件没有进入最大文件榜单。缓存中混入需保护文件时，不会将整个缓存目录标为可处理。

具体规则与官方路径依据见 [诊断规则](docs/DIAGNOSTIC-RULES.md)。

## 开发阶段

## 构建与验证

安装 Apple Command Line Tools 即可，无需完整 Xcode：

```bash
./scripts/build.sh
open "dist/DOJA Mac Doctor.app"
```

构建缓存和产物保存在本项目外置盘 `.build`。Swift 驱动在 exFAT 临时目录会失败，因此只有少量暂存编译文件放在独立 `/private/tmp/doja-doctor-build.*`，退出时清理这个本次创建的目录。构建不清理已有用户数据。应用采用本机 ad-hoc 签名，未做开发者分发签名或公证。

命令行只读扫描与实际验证：

```bash
dist/doctor-scan --help
dist/doctor-scan --output /absolute/path/report.json /absolute/path/to/scan
dist/doctor-scan --self-check
dist/doctor-scan --cleanup-self-check --fixture-root /private/tmp/doja-doctor-cleanup-fixtures --allow-small-internal-fixtures
dist/doctor-scan --monitor-self-check --fixture-root /private/tmp/doja-doctor-monitor-fixtures --allow-small-internal-fixtures
```

初版扫描记录见 [0.1 验收记录](docs/VALIDATION.md)，简化交互见 [0.2 验收记录](docs/VALIDATION-0.2.md)，监控见 [0.3 验收记录](docs/VALIDATION-0.3.md) 与 [监控规则](docs/MONITORING.md)。[清理测试](docs/CLEANUP-TESTS.md) 默认使用隔离目录模拟废纸篓；系统文件协调服务在开发工具的外层沙箱中可能被拒绝，正常应用权限环境测试仍保留全部安全检查。

## 本地数据与性能

不写持续扫描日志。容量历史仅包含本机指标与文件属性，位于 `~/Library/Application Support/DOJA Mac Doctor/space-history.sqlite`；主库不超过 16 MiB，事务期间可能另有回滚日志。最多保留 14 天、20,160 条采样、4,096 条目录观察、256 个异常；接近容量上限时优先轮换旧记录，不保证保存满 14 天。低于 100 MiB 停止数据库写入，最近异常仍可暂存内存并明确标注未保存。异常不能还原安装前或应用退出期间的历史。

最多保留 32 个目录书签和有容量限制的本机处理回执；回执仅包含路径、时间、结果与恢复位置，不包含文件内容，最多 1000 条、编码超过 2 MB 时不写入。优先保留恢复记录，本次处理最多 200 项且完整保留。扫描结果与比较驻留内存，用户导出时才写报告。扫描与清理复核在低优先级后台线程运行，约每 0.2 秒更新扫描进度。目录监控的详细工作预算、慢磁盘限制和统计口径见 [目录监控说明](docs/MONITORING-DIRECTORIES.md)。

逐个文件读取属性，最多保留两组各 50 个大文件；硬链接身份集仅记录多链接文件。扫描期间保留全量目录汇总与覆盖问题，先完成诊断、保护判断与处理清单核对。之后仅常驻最大 2000 个目录及根目录、1000 条问题、全部类型汇总和大文件榜单，并保存准确的全量计数；未保留细项不视为不存在。相邻扫描增长比较仅覆盖双方保留且完整的目录。扫描期间目录极多仍可能消耗显著内存，应缩小范围。扫描不是原子磁盘快照：会检测可观察到的目录/文件变更，持续写入应用的数据仍应稍后重扫。

代码分为 `DoctorCore`（元数据扫描、诊断和系统指标）、`DoctorApp`（SwiftUI 与目录授权）、`DoctorCLI`（真实扫描与独立验证）。Xcode 可以直接打开 `Package.swift`。
