# 勾选后移至废纸篓的安全边界

本版本实现“启动后扫描 → 显示建议 → 用户勾选 → 点击移至废纸篓”。扫描与准备建议保持只读，执行只发生在用户选择明确项目并点击按钮后。没有自动删除、管理员提权、后台清理、清空废纸篓或 Shell 删除命令。

## 当前可以勾选的范围

仅允许真实用户目录中以下应用父路径的已识别缓存子目录：

- `Library/Application Support/Codex`、`Library/Application Support/com.openai.codex`
- `Library/Caches/Codex`、`Library/Caches/com.openai.codex`

允许的处理单元为其中的 `GPUCache`、`Code Cache`、`ShaderCache`、`DawnCache`、`GrShaderCache`，不会把应用父目录或整个 `Library/Caches` 作为处理单元。缓存文件还必须符合已识别的 Chromium 缓存命名格式，例如 `index`、`data_0`、`f_000001`、十六进制缓存条目，以及已知的 `js`、`wasm`、`index-dir` 子目录。

一个名称看似缓存的目录如果混有代码、配置、会话、工程、媒体或无法确认用途的条目，整体保留。额外的 `.DS_Store` 或其他未识别条目也会保守地阻止整个目录处理。此限制可能使真实缓存不可勾选；不能为增加“可清理空间”而降低保护。

Codex 正在运行时，其缓存不可勾选。执行时再次检查应用状态；不会替用户结束任何进程。崩溃报告、日志、node_modules、构建目录、代理媒体、达芬奇渲染缓存及所有黄色或红色建议保持不可勾选。这些内容需要单独证明可恢复性与工程关联后才能扩展执行规则。

## 用户看到的建议如何绑定实际文件

准备建议需要完整、未取消的扫描记录，处理单元及其父目录必须同时处于已授权范围和本次扫描范围。没有对应完整记录、受保护条目、覆盖问题或扫描之后的大小、文件数量、根目录修改时间变化，都会阻止准备。

准备阶段不读取文件内容。它通过不跟随符号链接的目录描述符逐个检查全部条目，并捕获相对路径、设备、inode、文件类型与权限、所有者、flags、硬链接数、逻辑大小、分配块、mtime 与 ctime。父目录链也按描述符逐层打开并记录身份。用户勾选时从这份已准备的计划中取子集，不能通过“重新准备”偷偷接受后来新增或替换的文件。

符号链接（包括路径祖先）、其他磁盘挂载点、多个硬链接、云端占位文件、特殊文件、其他用户所有的条目和受保护 flags 都不能执行。单个目录最多复核 100,000 个条目、96 层和 60 秒；整份计划最多保留 200,000 个条目的清单，超出限制保留。计划超过 15 分钟需要重扫。

## 执行与恢复

执行前重复检查完整清单、目录祖先与应用运行状态。发现新增、修改或替换的任何文件，跳过此项。每一项独立报告结果，一项失败不会把下一项误报为成功。

随后通过父目录描述符和 `renameatx_np(..., RENAME_EXCL)` 把已验证缓存移动到同一父目录内的可见待恢复名称 `DOJA Mac Doctor Recovery <原缓存名> <UUID>`。排他重命名不会覆盖已存在的文件。再次复核移动后的完整清单，只有根目录由重命名产生的 ctime 变化被允许。借助系统文件协调，在最后一次状态检查之后调用 `FileManager.trashItem`。

系统废纸篓失败时尝试排他恢复原名称。原位置被重新创建、父目录发生变化或待恢复条目被替换时，不覆盖原位置，也不删除待恢复条目；结果提供恢复路径供用户查看。进程在暂存之后异常退出时，可见的待恢复名称仍便于在 Finder 中找到文件。

macOS 的废纸篓 API 接收路径，不提供“将某个已打开 inode 原子地移至废纸篓”的接口。文件协调防范遵循协调机制的应用，但无法完全消除同一用户权限下恶意进程在最后检查和系统移动之间制造的竞争。描述符、完整清单、排他暂存、停止正在运行的应用以及保留废纸篓恢复能力共同缩小这个窗口，不能宣称能够抵御任意恶意文件竞争。程序没有永久删除操作。

## 空间数字的含义

结果中的逻辑大小与分配大小只描述已移至废纸篓的文件，不能用作“已释放”数字。APFS 克隆与快照可能共享或保留数据块。移至废纸篓本身一般不会释放空间；本程序不清空废纸篓。

执行前后剩余容量是整个系统卷的实时观察，其他应用和系统活动也会改变它。两者差值不是本次操作的可归因回收量。成功提示只报告“已移至废纸篓，可恢复”，并明确没有立即释放空间的保证。

## 验证原则

自动测试仅使用独立临时用户目录和少量人工创建的缓存格式文件。测试可注入移动回调，将人工样本移至测试目录；真实系统废纸篓验证也只允许使用明确的人工样本。任何测试都不得清理电脑上的真实 Codex、影视工程、媒体或用户缓存。
