# 阶段二：重点目录的轻量监控

`DirectoryMonitor` 只监控调用方已经授权、实际可读取的最多 8 个本地目录。它不发现或授权新路径，不申请管理员权限，不跟随路径中的符号链接，不下载云端占位项。未知、无权限、消失或被替换的目录保留为“待确认”，不能当成空目录。

## 事件与核对预算

优先使用 macOS FSEvents 的目录变化通知，约 5 秒合并事件。事件只把已选重点目录标为待核对，不能直接计算目录占用或证明某个应用造成磁盘骤减。不会因每分钟采样剩余空间而每分钟扫描整盘。

一次核对周期的所有重点目录共享 5 秒元数据工作预算，每个目录最多读取 20,000 个常规文件。周期之间至少冷却 5 分钟；未完整核对的目录轮换处理，避免大目录一直挡住后面的目录。空间异常触发 `requestRefresh()` 也必须遵守同样的时间、文件数和冷却限制；重复请求合并，不创建并行扫描任务。

5 秒预算在元数据系统调用之间检查。磁盘很慢、暂不可用或内核的 `openat` 等调用阻塞时，无法保证在 5 秒墙钟时间内返回。暂停和取消也需要等待当前系统调用返回后生效。程序不会强制中止线程或绕过权限；界面读取观察快照始终只复制锁保护的数据，不等待后台扫描。

FSEvents 不可用时，降级为相同范围、相同预算、相同冷却的有限核对。事件丢失、事件 ID 异常、根路径变化、挂载和卸载都把相应结果标为待核对。核对命中预算仍为不完整，不会声称已经补齐整个子树。此行为依据 [Apple FSEvents 官方指南](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html) 对事件丢失与子树重新核对的要求。

## 基线与数字口径

已有完整扫描中的同路径 `DirectoryRecord` 可以作为初始显示参考，但不能直接成为目录监控的增长比较基线。完整扫描在全部扫描根之间去重硬链接的分配块；独立重点目录核对只在该目录内去重。首次独立有限核对完成后，才建立同范围可比较的监控基线，避免两种口径造成假的分配大小增长。

事件到达、预算耗尽、权限变化或暂停时，保留上次观察的数值和真实观察时间，同时设置 `isComplete = false` 与原因。没有完整观察时大小为 `nil`；不使用 0 代表未知。上次完整核对超过 30 分钟的对外观察也标为陈旧，只供参考。历史分析必须跳过不完整或陈旧数据。

逻辑大小和分配大小是两种不同的观测。分配大小仍不能说明 APFS 克隆或快照的数据块是否可以释放，也不能直接与全卷剩余容量变化一一对应。重点目录可能是父子关系，不能将各目录大小直接相加。

## 路径与生命周期

每次核对前后，都重新通过 `O_NOFOLLOW_ANY` 打开重点路径并核对设备与 inode，拒绝路径替换、链接、非本地磁盘或云端占位项。扫描器对子目录继续采用描述符相对的 `openat`/`fstatat` 检查，不跨卷，不读取内容。

FSEvents 有时使用 `/tmp` 或 `/var` 拼写，而授权路径可能是 `/private/tmp` 或 `/private/var`。这里只做已知系统拼写的文本事件匹配来标记已有目录待核对；文件访问始终使用原始已验证路径，不通过解析任意符号链接来统一路径。

监控使用一个串行后台队列、一个合并定时器和一个 FSEvents 流。状态更新用代次标记隔离旧回调；启动、停止、切换范围及暂停会取消当前有限核对。FSEvents 上下文保留弱引用桥接对象，配对 retain/release；停止时先 stop、invalidate，再 release。完整扫描与清理期间暂停目录核对，恢复后在预算内重新确认状态。

## 扫描器预算结果

`ScanOptions.maxFiles` 与 `maxDuration` 默认是 `nil`，既有用户主动深度扫描保持原来的行为。有限核对达到预算时返回 `ScanStatus.limited`，同时记录未完成原因和未完整目录。它与用户取消的 `.cancelled` 不同，也不能用于准备清理计划。
